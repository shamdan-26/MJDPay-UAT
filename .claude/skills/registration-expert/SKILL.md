# /registration-expert - navigate, extend and review the Registration suite

Input: `$ARGUMENTS`. Read `BusinessTestCases/Registration/README.md` first; it is the source of truth for layout and tags. Do not run Playwright/tsc after edits - the user verifies manually.

Wizard: Mobile -> OTP -> Business Info -> Financial -> Verification -> Nafath -> Products -> Contract -> Confirmation.

## 1. Where things live (layer first, wizard step second)

| Need | Location |
|---|---|
| Behaviour of a step | `functional/0N-<step>/` (`02-business-info/fields/` = one spec per field) |
| Cross-step flows, resume, resilience | `functional/journeys/` |
| Element/layout checks, mocked screen states | `ui/0N-<step>/` (`*Page`, `*Shell`, `*Form`, `*States`), `ui/shared/` = wizard chrome |
| Axe / perf budgets / visual snapshots | `non-functional/` |
| Gateway endpoints | `api/` (`RegistrationAPIFlow` is one serial chain - never split) |
| Auth/validation/replay, browser input attacks | `security/` |
| Admin portal <-> registration | `integration/` |
| Unrun ideas | `drafts/` (`*.draft.ts`, never executed by the suite) |
| Locators | `BusinessTestCases/pageElements/Registration/Registration<Step>Page.ts` |
| Shared code | `helpers/*`, re-exported by the barrel `RegistrationHelper.ts` |

New spec name: `Registration<Step><Topic>.spec.ts` (folder already names the layer). Every describe carries `@registration`, a layer tag and a step tag.

**Catalog by test type:** `Registration/TEST-CATALOG.md` groups all cases (id + title) as Functional / UI-UX / API / Security / Integration / Accessibility / Performance / Visual -> wizard step -> file, with counts. Generated by `node ../../scripts/registration-catalog.mjs TEST-CATALOG.md` run from `Registration/`. Regenerate it after adding, removing or skipping specs, and answer "how many X tests / what covers Y" from it. Category comes from the top folder (and file name inside `non-functional/`), so put a new spec in the folder of its type. Types with only drafts so far (not in the catalog): contract, fuzzing, load, localization, real-devices, privacy, config-matrix.

## 2. Which helper gets me to a step

| Goal | Call | Burns a pool identity? |
|---|---|---|
| Business Info, real | `goToInfoStep(page, mobile?)` | mobile only |
| Fill Business Info form | `fillBusinessInfo(infoPage, {crn, nationalId}, {profileType?, email?})` | no |
| Financial, real | `goToFinancialStep(page, creds?)` (default = cycles RESIDENT pool) | yes |
| Financial, own isolated identity | `goToFinancialStepWithDedicatedAsset(page)` | dedicated pool |
| Verification, real | `goToVerificationStep(page)`; `fillFinancialForm` / `fillVerificationForm` fill without submitting | yes |
| Products / Contract, real | `goToProductsStep(page)` / `goToContractStep(page)` (CITIZEN pool, NAFATH countdown handled) | yes |
| Any step, no OTP, no identity | `goToInfoStepMocked`, `goToFinancialStepMocked`, `goToVerificationStepMocked`, `goToOtpDialogMocked` + `mockOtpRequired`, `mockProfileType` | **no - prefer for read-only checks** |
| Raw API session | `openRegistrationSession(request, mobile)`, `postRegistration` | no |
| Verify provisioning | `getRegistrationProfileByMobileFromSql`, `getFullRegistrationDetailByMobileFromSql`, `getActivationNotification*FromMongo` | no |

OTP is the fixed value from `support/otp` on every environment (`getOtpFromDb` just returns it). Tests run on dev (`npm run test:dev`), never uat unless asked.

## 3. Helper files - one concern each

`registrationConfig` (URLs/data) - `registrationAssets` (pools, worker partition, used flags) - `registrationOtp` - `registrationSteps` (real drivers to Verification) - `registrationLateSteps` (Products/Contract) - `registrationUi` (PoS + dropdown interaction only) - `registrationMocks` (**all** route stubs and `goTo*Mocked`) - `registrationApi` - `registrationDb` - `infoStepForm` (Business-Info selectors + `gotoTab1`/`fillTab1*` for `02-business-info` specs).

Import from the barrel (`../RegistrationHelper`); API-only specs may import `helpers/registrationApi` directly. Barrel sections are ordered: config, identities, real drivers, UI, mocks, API, DB - add new exports to the matching section.

## 4. Identity-pool rules (easy to get wrong)

- Pools in `data/registrationAssets.json`: CITIZEN (Products/Contract), RESIDENT split into GENERAL / DEDICATED / MOBILE_REUSE, plus `uatOtpAssets`. Never draw from a reserved sub-pool through the general helper.
- A spent identity is dead: call `markResidentAssetUsed` / `markCitizenAssetUsed` with the outcome (`products`, `contract`, `nafath`, `already-registered`). `persistAssetUsedFlag` re-reads the file before writing because workers are separate processes.
- Explicit `crn`/`nationalId` passed to `goToFinancialStep` disables cycling on purpose (the caller tests that exact identity).
- Business Info conflicts arrive as HTTP 409 with no on-page text - use `submitBusinessInfo` (checks the response) rather than a bare Next click + text scan.
- Race Products against `products.productCards`, never `formSubTitle` (class shared by every step header).
- Specs sharing one expensive climb (`beforeAll`, serial) keep their order.

## 5. Review checklist (when asked to review/optimize)

Look for, in this order, and fix only what is safe without running tests:
1. **Duplicated flows** - the same fill/wait sequence in 2+ drivers -> extract one helper (done: `fillBusinessInfo`; Financial form fill lives only in `fillFinancialForm`).
2. **Wrong home** - helper in a file that doesn't match its concern (route mocks belong in `registrationMocks`, not `registrationUi`).
3. **Detached docblocks** - a JSDoc sitting above the wrong symbol (read each `/** */` and confirm the next line is its function).
4. **Unused imports/params/variables** (`void x;` hacks, params kept "for compatibility").
5. **Locator duplication** - raw selectors in specs/helpers that already exist on a page object (known debt: `infoStepForm.ts` constants mirror `RegistrationInfoPage`; migrate specs to the page object gradually, don't mass-rewrite unverified).
6. **Inline `getByRole('button', {name:/Loading/})`** -> `financialPage.loadingButton`.
7. **Barrel hygiene** - exports grouped, nothing exported that no file uses, specs not reaching into `helpers/*`.
8. **`isVisible({timeout})`** anti-pattern - Playwright ignores the timeout; use `waitFor`/`expect`.
9. New exceptions to POM/fixture rules are drift - flag them to the user instead of silently codifying.

Report: a short table (finding / file / action taken or recommended). Separate "fixed" from "flagged, needs your call".

## 6. Known open items

- `gotoTab1(page, context, asset)` has an unused `context` param (10 callers) - drop it in one sweep.
- `FINANCIAL_FIELD = 'textbox'` in `infoStepForm` is a role string, misleadingly named.
- Names `DEV_OTP_ASSETS` / `nextUatOtpAsset` / `generateFreshKSAMobile` say UAT/DEV inconsistently; rename together with their callers.
- `profile-type-MERCHANT/FREELANCER` testids still unmigrated in code.
- Hard-coded Arabic `'العقد'` step filter appears in `registrationUi` and `registrationLateSteps` - candidate for a `RegistrationProductsPage.contractStep` locator.
